# Dazzle — контекст проекта

Файл для будущих сессий Claude Code. Здесь только то, что не видно из кода за пять минут:
решения, договорённости с магазином, особенности окружения и порядок релиза.

**Правило: этот файл поддерживается в актуальном состоянии.** Меняешь поведение, версию,
редакцию или процесс релиза — правь соответствующий раздел в том же коммите.

---

## Что это

Настольное приложение (PySide6/PySide2 + SQLite) для импорта накладных поставщиков
в базу `shop.db` товароучётной программы **Tirika Shop**. Продавец загружает накладную
(Микадо, Аквилон, Форум, Москворечье), Dazzle сопоставляет строки с товарами базы,
считает цены и одним действием пишет приход в Tirika.

Пользователи — реальные магазины автозапчастей. Работает с боевой базой, поэтому
приоритет: не испортить данные. Есть `dry-run` и бэкап базы перед импортом.

- Репозиторий: `https://github.com/ahiokk/Dazzle` — **публичный**. Бизнес-данные,
  цены магазинов и выгрузки из базы в него не коммитим (см. `.gitignore`).
- Локальная папка проекта называется `AUTO-255_NAKLADNIE` — по первому магазину,
  а не по проекту; поиском по слову «dazzle» она не находится.

## Редакции (важно!)

Раньше сборки назывались по версии Windows (`win10`/`win7`). **Это неверная модель.**
Сборка = конкретный магазин. С 1.0.28 введены редакции (`tirika_importer/version.py`):

| Редакция | Магазин | Qt / Python | EXE | Ozon | Манифест |
|---|---|---|---|---|---|
| `auto255` | AUTO255 | PySide6 / 3.13 | `Dazzle.exe` | **да** | `updates/latest.json` |
| `lastochka` | Lastochka, Windows 7 | PySide2 / 3.8 | `DazzleWin7.exe` | нет | `updates/latest-win7.json` |
| `vag` | VAG | PySide6 / 3.13 | `DazzleVAG.exe` | нет | `updates/latest-vag.json` |

- Вкладка **Ozon** и заказ у **Микадо** нужны только AUTO255 (у них продажи на Ozon).
  Остальным магазинам их не показываем — гейт через `version.ozon_enabled()`.
- Редакция определяется на старте: `DAZZLE_EDITION` → имя exe → по умолчанию `auto255`
  (запуск из исходников). Посмотреть чужую редакцию:
  `$env:DAZZLE_EDITION="vag"; python dev_launch.py`.
- **Не переименовывать** `DazzleWin7.exe` и `updates/latest-win7.json`: на них завязано
  автообновление уже установленной копии Lastochka. Видимые названия менять можно.
- Настройки у всех редакций лежат в общем `%APPDATA%\Dazzle\settings.json`. На реальных
  машинах стоит одна редакция, конфликта нет. При запуске чужой редакции на своей машине
  `update_manifest_url` перепишется на её канал — это штатное поведение
  (`_normalize_update_manifest_url`), обратно чинится сам при следующем запуске своей.

## Ценообразование — договорённости с магазином

- Обычная наценка (`markup_percent`) — расчёт «Продажи новой», округление вверх до
  шага `round_step`. Значение у каждого магазина своё, задаётся в настройках.
- **Минимальная наценка `min_markup_percent` = 50%** (`enforce_min_markup`).
  Магазин сказал: дешевле 50% не продаём никогда. Если цена, которая после импорта
  окажется в базе, даёт наценку ниже минимума — Dazzle сам поднимает цену продажи
  **до обычной наценки** (не до минимума!), а минимум работает как нижняя граница
  на случай, если обычная наценка окажется меньше минимальной.
  Логика: `_enforce_min_markup` в `gui.py` + чистая `enforce_min_markup_price` в `db.py`.
  Строка помечается: в «Предупреждении» коротко `35% → 76%`, полная фраза — в подсказке.
  Чтобы поднятая цена доехала до базы, строке ставится `_force_update_sell_price`.
- **Цвета колонки «Наценка»** (просьба магазина, чтобы продавец видел аномалии глазами):
  ниже минимума — красный, 50–75% — оранжевый, 75–100% — зелёный, 100–200% — жёлтый,
  выше 200% — красный. Логика: `markup_band` в `db.py`, цвета — `MARKUP_BAND_COLORS`
  в `gui.py`, легенда — в нижней панели и в настройках.
- Старая настройка «Порог красного, %» (`price_alert_threshold_percent`) и вся механика
  `price_alert` **удалены** в 1.0.28 — заменены диапазонами цветов. Не возвращать.

## Интерфейс — принятые решения

- Подсказки в таблице короткие, по одной строке: на текстовых колонках — полный текст
  ячейки, на «Предупреждении» — расшифровка, на остальных — `артикул · название`.
  Длинные многострочные подсказки не нравятся: «слишком много информации».
- Задержка подсказки — 2 секунды, и `SH_ToolTip_FallAsleepDelay = 0`, иначе Qt после
  первой подсказки показывает следующие мгновенно и они «сыплются» при движении мышью
  (`ToolTipDelayStyle` в `gui.py`).

## Сборка

```powershell
.\build_installer.ps1 -Edition auto255 -RebuildExe     # Dazzle-AUTO255-Win10-Setup-<ver>.exe
.\build_installer.ps1 -Edition vag -RebuildExe         # Dazzle-VAG-Win10-Setup-<ver>.exe
.\build_installer_lastochka.ps1 -RebuildExe            # Dazzle-Lastochka-Win7-Setup-<ver>.exe
```

- Три сборки можно гонять **параллельно**: у каждой свой `--workpath build\<exe>`.
  При параллельном запуске добавляй `-SkipDeps`, иначе они одновременно полезут
  `pip install` в один venv. Одна сборка ≈ 6 мин PyInstaller + 4 мин Inno.
- В имени установщика подписаны магазин и версия Windows — так же в мастере установки
  и в «Программах и компонентах». Ярлык автозапуска во всех редакциях остаётся
  `Dazzle.lnk`: этим же файлом управляет кнопка «Добавить в автозапуск» внутри
  программы (`startup.py`), иначе после установки будет два автозапуска.
- `ISCC.exe` (Inno Setup 6) ищется в `%ProgramFiles%`, `%ProgramFiles(x86)%` и
  `%LOCALAPPDATA%\Programs\Inno Setup 6` — на этой машине он в `%LOCALAPPDATA%`.
- **Антивирус ломает параллельную упаковку.** При трёх одновременных сборках Inno падает
  на последнем шаге: `Resource update error: EndUpdateResource failed ... (110)` —
  антивирус держит свежий `Setup.exe`. EXE при этом уже собран, достаточно повторить
  только шаг Inno: `.\build_installer_lastochka.ps1 -SkipDeps` (без `-RebuildExe`).
  Лечится добавлением `installer_output` в исключения антивируса.
- Скрипты сборки печатают SHA256 в конце — но если запускаешь их в фоне и ждёшь файл,
  **условие ожидания должно ловить и провал тоже**, иначе упавшая сборка выглядит как
  «ещё идёт» (уже наступали).
- PyInstaller 6 (auto255/vag) кладёт данные в `_internal\`, PyInstaller 5.13 (lastochka) —
  в корень папки сборки. `theme.py` ищет иконки через `Path(__file__).parent.parent`,
  и оба варианта в это попадают.

## Релиз и автообновление

Апдейтер (`tirika_importer/updater.py`) читает JSON-манифест своей редакции, и:
- принимает установщик только по **https** с `github.com` / `githubusercontent.com`;
- требует корректный `sha256` (64 hex) — без него обновление отклоняется;
- сравнивает версии, скачивает, проверяет хеш, ставит тихо и перезапускает приложение.

Порядок выпуска версии:
1. Поднять `APP_VERSION` в `tirika_importer/version.py`.
2. Собрать установщики нужных редакций (скрипт печатает SHA256 в конце).
3. `gh release create v<ver> <файлы> --title ... --notes ...`
4. Прописать в манифесты (`updates/latest*.json`) version, url на ассет релиза, sha256, notes.
5. Закоммитить и запушить манифесты в `main` — после этого клиенты увидят обновление.

**Порядок важен:** сначала релиз с ассетами, потом пуш манифестов. Если запушить манифест
на несуществующий ассет — у клиентов обновление упадёт на скачивании.

## Окружение (грабли этой машины)

- `.venv` в проекте был битый (numpy/pandas/lxml ставились наполовину). Чинится
  `pip install --force-reinstall`. Для прогонов кода надёжнее `.build_venv_py313` —
  там установлен полный `requirements.txt`.
- Тесты: `.\.venv\Scripts\python.exe -m pytest -q` (60 тестов на 1.0.28).
- Боевая база Tirika: `%ProgramFiles(x86)%\Tirika Shop\shop.db` (~7000 товаров).
  Чтение каталога работает без прав администратора, запись — нет. Копии баз для
  опытов лежат в `db_examples\` (папка в `.gitignore`).
- Для демонстраций: `python dev_launch.py --invoice examples\demo_nakladnaya.xls`
  (запуск без UAC, `--invoice` грузит накладную сразу). Демо-накладная синтетическая,
  собрана из реальных кодов базы так, чтобы попасть во все диапазоны наценки;
  она в `.gitignore` — цены магазина в публичный репозиторий не выкладываем.
  **Импорт в базу на ней не запускать.**
- Проверить таблицу без экрана: `QT_QPA_PLATFORM=offscreen` + скрипт, который читает
  `window.table` — так проверялись цены, цвета и подсказки на реальных данных.
- В bash-heredoc не писать `\\` (обратные слэши схлопываются, `\b`/`\r` ломают строки) —
  для правки файлов использовать редактор, а не питон-скрипт в heredoc.
